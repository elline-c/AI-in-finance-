🛡️ Bank Statement Screening — UI demo

Static snapshots of both user interfaces, rendered from real cases run through the actual screening pipeline. Click through — links work offline.

CUSTOMER

Loan applicant portal

The applicant's view. Never shows risk scores, evidence, or "fraud" language — only neutral status.

  1. Apply — submit company details + statement PDF
  2. Confirmation (clean) → reference + "verified"
  3. Track status — verified
  4. Confirmation (escalated) → "being reviewed"
  5. Track status — action needed (analyst asked for more info)
  6. Track-by-reference form
ANALYST

Credit-analyst console

The reviewer's view. Full scores, evidence, and the per-stage workflow. The machine never rejects on its own.

  1. Screening queue — all cases + status badges
  2. Case overview (tampered) — scores + findings-by-stage + decision panel
  3. Flagged transactions — every row + the evidence that flagged it
  4. Pipeline stages — what each agent produced
  5. Case overview (clean) — auto-cleared, all stages "clear"
The story these snapshots tell: Meridian Trading uploads a tampered statement → the customer sees a calm "being reviewed"; the analyst sees the risk score, the flagged rows, and every stage's evidence, then requests more information → the customer now sees a neutral "action needed" with the reviewer's message, and can re-submit. Harbourline's clean statement is auto-cleared and the customer sees "verified".

Static demo caveats: forms don't submit (buttons are inert) and the "Statement PDF" link points back to this index — those need the live app: uvicorn fraud_detect.webapp:app and uvicorn fraud_detect.customer_app:app.
